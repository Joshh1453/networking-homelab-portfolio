# Documentation and Change Management

I use Obsidian to create and maintain technical documentation for my homelab, including infrastructure decisions, implementation work, troubleshooting outcomes, and recovery procedures.

I use Git and GitHub to version that documentation and preserve a clear history of meaningful changes. My detailed operational records remain in a private repository, while this public repository is maintained as a sanitized portfolio.

Public updates are grouped into clear commits so readers can follow the progression of network design, virtualization, wireless deployment, monitoring, and incident-response work without exposing live infrastructure details.

I use commit signing for future portfolio updates to provide a verifiable record that changes were authored from my configured development environment.
